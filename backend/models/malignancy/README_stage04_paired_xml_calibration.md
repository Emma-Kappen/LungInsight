# LungInsight_v2 — Stage 04 paired XML calibration

## Purpose

The recent affine feature-scale alignment experiment did not improve validation performance. This experiment replaces *unsupervised marginal matching* with a paired, supervised calibration:

1. Read only the fixed H5 reader-label and identity datasets for canonical **train and validation** sample indices. The H5 `patches` dataset is never accessed.
2. Parse the actual XML `ResponseHeader` so matching uses the XML file's own Study/Series UIDs, not a guessed spatial group.
3. Match XML reader ratings to H5 physical-nodule samples using an exact signature of all eight non-malignancy ratings in the same patient/study/series. `malignancy` is not used to establish identity. `internalStructure` and `calcification` are identity-matching fields only, not Stage 04 predictors.
4. Join the paired annotations to the existing frozen Stage 03 `train.npz` / `val.npz` by canonical `sample_index`.
5. Fit six train-only monotonic isotonic calibrators from each Stage 03 scalar output to the corresponding XML nodule-median rating.
6. Fit the Stage 04 malignancy regressor on XML nodule-median ratings for the same matched training nodules. Compare raw versus calibrated Stage 03 validation inputs and constant baselines.

The Stage 03 checkpoints and fixed split are untouched. `test.npz` is never opened, test-sample H5 labels are never read, no CT `PixelData` is read, and H5 patches are never accessed. The H5 is used only for train/validation annotation labels and sample identity. The XML scan reads headers to identify train/validation XML files, but parses annotation bodies only for XML files matching the train/validation series in the existing split.

## Files

- `train_stage04_paired_xml_calibration.py` — pairing, feature calibration, Stage 04 training, and validation report.
- `predict_stage04_xml_calibrated.py` — inference adapter for Stage 03 `predictions.json`.

## Training command

```powershell
python .\LungInsight_v2\backend\models\malignancy\train_stage04_paired_xml_calibration.py `
    --lidc-root .\datasets\LIDC `
    --h5 .\datasets\LIDC\lidc_patches.h5 `
    --split-json .\LungInsight_v2\backend\models\nodule_ranker_3d_distributional_v1\split.json `
    --features-dir .\LungInsight_v2\backend\models\malignancy\frozen_features `
    --out-dir .\LungInsight_v2\backend\models\malignancy\xml_paired_calibration_v1
```

It uses CPU. Dependencies are the project's existing `numpy`, `h5py`, `scikit-learn`, and `joblib` packages. It does not run DICOM-header indexing.

If the output directory already exists and contains files, choose a new `--out-dir` or deliberately add `--overwrite`.

## Outputs

- `training_report.json` — matching coverage, per-attribute validation calibration, raw-vs-calibrated Stage 04 validation, and baseline metrics.
- `matched_xml_nodule_table.csv` — train/validation XML ratings matched to the frozen H5 nodule sample index.
- `stage04_ranker_validation_predictions.csv` — raw and calibrated Stage 04 predictions on the existing validation archive.
- `stage04_xml_calibrated_malignancy.joblib` — model plus the six train-fitted calibrators.

## How to assess it

First inspect `matching_stats` and `matched_physical_nodules`. Low match coverage means the model should not be accepted; do not fall back to spatial guesses automatically. Inspect `feature_calibration_validation` for held-out Spearman correlation and MAE versus XML medians per attribute. Finally inspect `stage04_ranker_validation` for raw and calibrated predictions against the same validation targets and constant baseline. A wider prediction distribution by itself is not a success: calibrated validation MAE should improve over the baseline and ordinal agreement should be meaningful.

Training archive predictions were generated by the fixed rankers on their own training patients (in-sample). Validation metrics use the disjoint validation patients; thus validation is the real check of calibration generalization. No test data is used for model selection.

## Inference command

After reviewing the report, run from the same repository parent:

```powershell
$predictions = Read-Host "Enter the path to the existing Stage 03 predictions.json"
python .\LungInsight_v2\backend\models\malignancy\predict_stage04_xml_calibrated.py `
    "$predictions" `
    --model .\LungInsight_v2\backend\models\malignancy\xml_paired_calibration_v1\stage04_xml_calibrated_malignancy.joblib
```

The adapter reads only each candidate's six Stage 03 attribute outputs, calibrates them, and outputs a predicted **LIDC reader malignancy/suspicion rating** on the 1–5 scale. It does not output a calibrated probability of cancer or a pathology-confirmed diagnosis.
